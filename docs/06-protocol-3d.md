# 06. Android-клиент «Третий Мир: Война Королей 3D» (2.0.112)

APK `start.browser.gameTWWK` 2.0.112 (targetSdk 36, minSdk 21). Разобран декомпиляцией
(dex2jar + CFR/Vineflower, androguard). Код обфусцирован R8 и «мусорными» вычислениями,
но имена сетевых команд и типов сохранились в строках.

## Что это за клиент

Это **движок-«мини-браузер»** (`MiniBrowserActivity`), а не игра с зашитыми экранами:

- в клиенте **нет игровых текстов** («Замок», «Ратуша», «Логин» и т. п.) — их присылает сервер;
- интерфейс — окна, которые сервер описывает **текстовой разметкой** или объектами;
- есть интерпретатор собственного скриптового языка, 3D-движок (OpenGL) и локальные ресурсы:
  модели и текстуры замка, земель, мира, короля, крестьян (`assets/raw/*`), стили окон (`assets/Style`),
  карты (`assets/Map/Map/*.map`), шрифты, музыка.

Значит, «поднять» клиент = написать серверную часть игры в формате этого движка.
Наш сервер: [`server/src/tw3d/`](../server/src/tw3d).

## Адрес сервера

`assets/conect.conf`: `G` + список через `|`: `Gsocket://mmog1.com:5005|socket://mmog2.com:5005`.
Меняется без правки кода — [`tools/repack_apk.py`](../tools/repack_apk.py) заменяет файл, пересобирает zip
(с выравниванием, `resources.arsc` без сжатия) и подписывает APK схемами v1+v2 (проверено `apksigtool`,
`jarsigner`, androguard). Сервер также может прислать новый список хостов (команда `NWHOST`).

## Транспорт (протокол v56)

| Шаг | Байты |
|---|---|
| Клиент после подключения | `38 0F` (56, 15) |
| Сервер | `[версия, минимальная]` — клиент работает с `min(версия, 56)`; если вторая > 56 → «клиент устарел», открывается twwk.ru. Наш сервер шлёт `38 38` |
| Пакет (оба направления) | `[канал u8][длина varint][payload]` |
| payload | `[сжато bool][заголовок][тело]` (сжатие клиент при отправке не использует) |
| заголовок | `u32 длина` таблицы шрифтов/фонов; при 0 далее `varint 0, varint 0` → пусто = `00 00 00 00 80 80` |

**varint** (`y.c.d`): 0…249 → 1 байт `n-128`; < 65536 → `7E` + `short(n-32768)`; иначе `7F` + `int32`.
**Строка**: `varint длина` + UTF-16BE (в протоколе ≤ 27 — cp1251); длина 0 = null.

Каналы: **0** — сообщения (`o.a`), **1** — файлы `XFILE` (`M.a`), **2** — `D.c.o`.

## Сообщение (канал 0)

`int32 категория, int32 команда, объект` (класс `i.i`). Категория и команда — **имена до 6 символов**,
закодированные числом: каждая буква → 1…26, цифра → 27…36, `:`→37, `\`→38, прочее→39;
`сумма(код × 40^позиция) + INT_MIN` (регистр не важен). Реализация: `nameHash` / `nameOf` в `tw3d/protocol.js`.

### Типы объектов (реестр `J1.b.d`)
| ID | Тип | Формат |
|---|---|---|
| −1 | null | — |
| 1 | число (`k.e`) | int32 |
| 5 | список (`i.g`) | int32 N, N объектов |
| 6 | пусто (`i.j`) | — |
| 7 | команда-ссылка (`w.d`) | int32 кат, int32 команда, объект, char адресат |
| 8 | строка (`k.h`) | строка |
| 9 | пара (`i.c`) | int32, int32 |
| 10 | 5 строк + байт (`i.e`) | |
| 12 | логическое (`k.b`) | bool |
| 21 / 22 | диалог / окно (`u.d` / `u.c`) | сложный объект |
| 25–27 | меню (`v.*`) | |
| 28 | словарь (`i.l`) | varint N, N × (int32 ключ-имя, объект) |
| 29 | ссылка на объект (`i.m`) | int32 |
| 99–102 | стиль, фон, шрифт, … | |

## Жизненный цикл

1. Рукопожатие.
2. Если окон нет — клиент шлёт **`USER.START`** (с системной информацией).
3. Сервер открывает окна: **`win.ADDDIL`** со строкой-разметкой; **`win.CLOSE`** закрывает верхнее окно.

## Разметка окна (строка в `ADDDIL`, разбор `r.d.x`)

| Фрагмент | Значение |
|---|---|
| текст | слова через пробел; `\n` — новая строка, `\t` — табуляция |
| `{имя}` | картинка; `!` в начале — файл из assets клиента: `{!Style/Glass.png}` |
| `{~(ш;в)имя}` | картинка заданного размера |
| `{?кат:имя}` | значение из памяти клиента |
| `{X.кат.команда(арг,…);}текст{;}` | ссылка; аргументы — числа или `'строки'` |

Адресат ссылки `X`: **`s` — сервер**, `g` — сам клиент (глобально, например `{g.win.CLOSE();}`),
`l` — текущее окно, `t` — таймер.

## Ввод текста

Сервер: `кат.INPTXT` со списком `[кат_ответа, команда_ответа, начальный текст, макс. длина, флаги]`
(флаг `65536` — пароль). Клиент открывает системное поле ввода и шлёт серверу
`кат_ответа.команда_ответа(строка)` (фигурные скобки заменяются на квадратные).

## Прочие команды (константы `o.c`)

`win`, `app`, `exit`, `style`, `FILES`, `SYSTEM`, `ANIM`, `MEM`/`MEMQ` (хранилище значений),
`MAP3D` (3D-карта), `SMENU`, `SOUND` (`PLAY_MUSIC`, `PLAY_SOUND`, `PLAY_ALARM`), `SOCIAL`, `PROMOT`,
`NWHOST` (новые хосты), `time`, `smiles`, мышь/касания (`MDOWN`, `MUP`, `MCLICK`, `MMOVE`), `PAINT`,
`CLOSE`, `ADDDIL`, `add`/`del`/`delAll`, `INFOIN`, `RELOAD`, `GETFIL`, `CONSER`, `GCM*`.
По запросу `g.c.K` клиент отправляет данные устройства (модель, android_id, IMEI) — наш сервер это не запрашивает.

## Что работает на нашем сервере

Приветственное окно → регистрация (логин и пароль через поле ввода, выбор расы) → вход →
окно замка (ресурсы, стройки) → списки зданий замка и земель → стройка/улучшение → «Готово» →
выход. Мир общий с J2ME- и браузерным клиентом. Проверено смоук-тестом протокола
(`server/test/smoke3d.js`); на реальном телефоне — см. [05-local-testing.md](05-local-testing.md).

## Следующие шаги

- Передача файлов (`XFILE`, канал 1), стили (`style`), звук.
